# ภาพรวมของโปรเจกต์

นี่คือเว็บแอปพลิเคชันที่พัฒนาด้วย Vue.js สำหรับ Frontend และ PHP สำหรับ Backend โดยสภาพแวดล้อมทั้งหมดถูกจัดเก็บใน Docker container

**Frontend:**
- แอปพลิเคชัน Vue.js ที่สร้างด้วย Vite
- ใช้ `axios` สำหรับการส่งคำขอ HTTP และ `vue-router` สำหรับการจัดการเส้นทาง
- ซอร์สโค้ดอยู่ที่ไดเรกทอรี `frontend/src`

**Backend:**
- แอปพลิเคชัน PHP ที่เชื่อมต่อกับฐานข้อมูล MySQL
- ใช้ตัวแปรสภาพแวดล้อมสำหรับข้อมูลการกำหนดค่าฐานข้อมูล
- เปิดใช้งาน CORS สำหรับการพัฒนาในเครื่อง
- ซอร์สโค้ดอยู่ที่ไดเรกทอรี `backend`

**ฐานข้อมูล:**
- ฐานข้อมูล MySQL 5.7
- มีบริการ `phpmyadmin` สำหรับการจัดการฐานข้อมูล

# การสร้างและรันโปรเจกต์

โปรเจกต์นี้ถูกออกแบบมาเพื่อรันด้วย Docker Compose

**ในการเริ่มบริการทั้งหมด:**
```bash
docker-compose up -d
```

**ในการหยุดบริการทั้งหมด:**
```bash
docker-compose down
```

**การพัฒนา Frontend:**
ในการรันเซิร์ฟเวอร์การพัฒนา Frontend:
```bash
cd frontend
npm install
npm run dev
```

**Backend:**
Backend PHP ถูกให้บริการโดยบริการ `php` ในไฟล์ `docker-compose.yml` และทำงานบนพอร์ต 8000

# ความคืบหน้า

- **ระบบการเข้าสู่ระบบ (Login System):** เสร็จสิ้น
- **ระบบกำหนดสิทธิ์ผู้ใช้งาน (User Role Management):**
    - **Admin:** เสร็จสิ้น
    - **Teacher:** เสร็จสิ้น
    - **Student:** เสร็จสิ้น
- **ระบบจัดการผู้ใช้งาน (User Management System):** ย้ายไปที่ `AdminUsers.vue`
- **ระบบแสดงโครงงานย้อนหลัง (Past Project Display System):** เสร็จสิ้น (มีการเพิ่มการค้นหาและการเรียงลำดับ)
- **ระบบจัดการเอกสาร (Document Management System):**
    - **Admin:** เสร็จสิ้น (อัปโหลด, ดาวน์โหลด, ลบ)
    - **Teacher:** เสร็จสิ้น (ดาวน์โหลด, อัปโหลด, ตรวจสอบสถานะ, ให้ความคิดเห็น)
    - **Student:** เสร็จสิ้น (ดาวน์โหลด, อัปโหลด, ดูสถานะและความคิดเห็น)
- **การออกแบบส่วนติดต่อผู้ใช้ (User Interface Design):** มีการรองรับ Responsive Design ในระดับหนึ่ง
- **ข้อจำกัดการเข้าถึงระบบ (System Access Restrictions):** ต้องกำหนดค่าที่ระดับเซิร์ฟเวอร์

# ขอบเขตของการดำเนินงาน

โครงงานนี้เป็นการพัฒนาเว็บไซต์เพื่อใช้ภายในมหาวิทยาลัย โดยมีวัตถุประสงค์เพื่ออำนวยความสะดวกในการจัดการข้อมูลที่เกี่ยวข้องกับโครงการสหกิจศึกษา โดยมีขอบเขตของการดำเนินงาน ดังนี้

## การพัฒนาเว็บไซต์
-ใช้ภาษา PHP ในฝั่ง Backend
-ใช้ Vue.js ในฝั่ง Frontend
-เชื่อมต่อกับฐานข้อมูล MySQL สำหรับจัดเก็บและจัดการข้อมูล
-เชื่อมต่อกับ phpMyAdmin เพื่อช่วยในการบริหารจัดการฐานข้อมูลอย่างสะดวกและปลอดภัย

## ระบบการเข้าสู่ระบบ (Login System)
- จำกัดสิทธิ์การเข้าใช้งานเฉพาะผู้ที่มีบัญชีผู้ใช้ ได้แก่:
    - ผู้ดูแลระบบ (Admin)
    - อาจารย์ (Teacher)
    - นิสิต (Student) ที่ลงทะเบียนเรียนในรายวิชาสหกิจศึกษา
- ผู้ใช้จะต้องเข้าสู่ระบบก่อนจึงจะสามารถเข้าถึงฟังก์ชันต่าง ๆ ได้

## ระบบกำหนดสิทธิ์ผู้ใช้งาน (User Role Management)
- **แอดมิน** :
    - จัดการข้อมูลผู้ใช้งานทั้งหมด (เพิ่ม/ลบ/แก้ไข) - ย้ายไปที่ `AdminUsers.vue`
    - เข้าถึงข้อมูลโครงงาน
    - อัปโหลด ดาวน์โหลด และลบเอกสารในระบบ
- **อาจารย์** :
    - เข้าถึงข้อมูลโครงงาน
    - ดาวน์โหลดแบบฟอร์ม และอัปโหลดเอกสารที่เซ็นแล้ว ได้แก่ CS01–CS05 และเล่มรายงาน
    - ตรวจสอบไฟล์เอกสารที่นิสิตส่งเข้ามา พร้อมส่งกลับ พร้อมแสดงสถานะ (ผ่าน/ไม่ผ่าน) และสามารถใส่ความคิดเห็นได้
- **นิสิต** :
    - เข้าถึงข้อมูลโครงงาน
    - ดาวน์โหลดเอกสารแบบฟอร์ม CS01–CS05 (PDF)
    - ดาวน์โหลดตัวอย่างเล่มรายงาน (.docx)
    - อัปโหลดไฟล์ CS01–CS05 และเล่มรายงานในรูปแบบ PDF

## ระบบจัดการผู้ใช้งาน (User Management System)
- สำหรับผู้ดูแลระบบ เพื่อเพิ่ม ลบ แก้ไข และดูรายชื่อผู้ใช้งานทั้งหมดภายในระบบ (ย้ายไปที่ `AdminUsers.vue`)

## ระบบแสดงโครงงานย้อนหลัง
- แสดงรายการโครงงานในช่วง 5 ปีที่ผ่านมา
- สามารถเรียงลำดับตามชื่อโครงงานและชื่ออาจารย์ที่ปรึกษา
- รองรับการค้นหาเพื่อให้นิสิตรุ่นใหม่ใช้เป็นแนวทาง

## ระบบจัดการเอกสาร
- นิสิตสามารถดาวน์โหลดแบบฟอร์ม CS01–CS05 ได้ในรูปแบบ PDF
- สามารถอัปโหลดเอกสารเวอร์ชันที่ลงนามแล้ว เพื่อส่งให้อาจารย์ตรวจสอบ
- อาจารย์สามารถดาวน์โหลด ตรวจสอบ และส่งเอกสารกลับให้แก่นิสิต
- สามารถกำหนดสถานะของเอกสารได้ (ผ่าน / ไม่ผ่าน)
- หากไม่ผ่าน อาจารย์สามารถแสดงความคิดเห็นหรือข้อเสนอแนะในการแก้ไขได้

## ระบบดาวน์โหลดตัวอย่างเล่มรายงาน
- จัดเตรียมไฟล์ตัวอย่างเล่มรายงานและเอกสารที่เกี่ยวข้องเพื่อให้นิสิตใช้เป็นแนวทางในการจัดทำรายงาน

## การออกแบบส่วนติดต่อผู้ใช้ (User Interface Design)
- รองรับการแสดงผลแบบ Responsive เพื่อให้สามารถใช้งานได้บนอุปกรณ์หลากหลายรูปแบบ ทั้งคอมพิวเตอร์ แท็บเล็ต และโทรศัพท์มือถือ

## ข้อจำกัดการเข้าถึงระบบ
- ระบบจะจำกัดการเข้าใช้งานเฉพาะภายในเครือข่ายของมหาวิทยาลัย หรือเซิร์ฟเวอร์ที่ได้รับอนุญาตเท่านั้น เพื่อรักษาความปลอดภัยและความเป็นส่วนตัวของข้อมูล

# โครงสร้างฐานข้อมูล (Database Schema)

นี่คือโครงสร้างฐานข้อมูลที่ใช้ในปัจจุบัน:

## 1. ตาราง `users` (ข้อมูลผู้ใช้งาน)
ใช้สำหรับจัดเก็บข้อมูลผู้ใช้งานระบบทั้งหมด (Admin, Teacher, Student) และข้อมูลการเข้าสู่ระบบ

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `id` | INT (PK) | รหัสเฉพาะของผู้ใช้งาน |
| `email` | VARCHAR | อีเมลสำหรับเข้าสู่ระบบ (Unique) |
| `username` | VARCHAR | ชื่อผู้ใช้งานสำหรับเข้าสู่ระบบ (Unique) |
| `password` | VARCHAR | รหัสผ่านที่ถูกแฮช |
| `full_name` | VARCHAR | ชื่อ-นามสกุลของผู้ใช้งาน |
| `role` | ENUM | บทบาทของผู้ใช้งาน ('admin', 'teacher', 'student') |
| `session_token` | VARCHAR | โทเค็นสำหรับจัดการเซสชัน (Unique) |

## 2. ตาราง `advisors` (ข้อมูลอาจารย์ที่ปรึกษา)
ใช้สำหรับจัดเก็บข้อมูลเพิ่มเติมของอาจารย์ที่ปรึกษาโครงงาน

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `advisor_id` | INT (PK) | รหัสเฉพาะของอาจารย์ที่ปรึกษา |
| `user_id` | INT (FK) | อ้างอิงถึง `users.id` |
| `department` | VARCHAR | ภาควิชา |

## 3. ตาราง `academic_terms` (ข้อมูลภาคการศึกษา)
ใช้สำหรับจัดเก็บข้อมูลปีและภาคการศึกษาต่างๆ

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `term_id` | INT (PK) | รหัสเฉพาะของภาคการศึกษา |
| `academic_year` | INT | ปีการศึกษา (เช่น 2568) |
| `term_name` | VARCHAR | ชื่อภาคการศึกษา ('เทอมต้น', 'เทอมปลาย', 'ภาคฤดูร้อน') |

## 4. ตาราง `projects` (ข้อมูลโครงงาน)
เป็นตารางหลักสำหรับจัดเก็บข้อมูลของแต่ละโครงงาน

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `project_id` | INT (PK) | รหัสเฉพาะของโครงงาน |
| `project_name` | VARCHAR | ชื่อโครงงาน |
| `group_name` | VARCHAR | ชื่อกลุ่ม |
| `advisor_id` | INT (FK) | อ้างอิงถึง `advisors.advisor_id` |
| `term_id` | INT (FK) | อ้างอิงถึง `academic_terms.term_id` |
| `abstract` | TEXT | บทคัดย่อของโครงงาน |

## 5. ตาราง `students` (ข้อมูลนิสิต)
ใช้สำหรับจัดเก็บข้อมูลเพิ่มเติมของนิสิต

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `student_id` | VARCHAR (PK) | รหัสนิสิต |
| `user_id` | INT (FK) | อ้างอิงถึง `users.id` |

## 6. ตาราง `project_members` (ตารางเชื่อมข้อมูลนิสิตและโครงงาน)
ใช้สร้างความสัมพันธ์แบบ Many-to-Many ระหว่าง `projects` และ `students`

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `project_id` | INT (FK) | อ้างอิงถึง `projects.project_id` |
| `student_id` | VARCHAR (FK) | อ้างอิงถึง `students.student_id` |

## 7. ตาราง `document_templates` (ข้อมูลเทมเพลตเอกสาร)
ใช้สำหรับจัดเก็บลิงก์ดาวน์โหลดไฟล์เทมเพลตสำหรับทำเล่มรายงาน

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `template_id` | INT (PK) | รหัสเฉพาะของเทมเพลต |
| `template_name` | VARCHAR | ชื่อประเภทเอกสาร (เช่น 'หน้าปก') |
| `pdf_url` | VARCHAR | URL สำหรับดาวน์โหลดไฟล์ .pdf |
| `docx_url` | VARCHAR | URL สำหรับดาวน์โหลดไฟล์ .docx |

## 8. ตาราง `submission_document_types` (ประเภทเอกสารที่ต้องส่ง)
ใช้กำหนดประเภทของเอกสารที่นิสิตต้องอัปโหลดส่งในระบบ

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `doc_type_id` | INT (PK) | รหัสเฉพาะของประเภทเอกสาร |
| `doc_code` | VARCHAR | รหัสเอกสาร (เช่น 'CS01') |
| `doc_name` | VARCHAR | ชื่อเต็มของเอกสาร (เช่น 'ไฟล์เอกสารโครงร่าง') |

## 9. ตาราง `submitted_documents` (ข้อมูลเอกสารที่นิสิตส่ง)
ใช้สำหรับบันทึกไฟล์เอกสารที่แต่ละโครงงานได้อัปโหลดเข้ามาในระบบ

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| `submission_id` | INT (PK) | รหัสเฉพาะของการส่ง |
| `project_id` | INT (FK) | อ้างอิงถึง `projects.project_id` |
| `doc_type_id` | INT (FK) | อ้างอิงถึง `submission_document_types.doc_type_id` |
| `file_path` | VARCHAR | ตำแหน่งที่จัดเก็บไฟล์ที่อัปโหลด |
| `uploaded_at` | DATETIME | วันและเวลาที่อัปโหลด |
| `uploader_student_id` | VARCHAR (FK) | อ้างอิงถึง `students.student_id` |
