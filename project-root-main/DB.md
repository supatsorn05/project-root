### การออกแบบโครงสร้างฐานข้อมูล (Database Schema)

จากการวิเคราะห์ข้อมูลในไฟล์ PDF สามารถออกแบบโครงสร้างฐานข้อมูลสำหรับระบบจัดการโครงงานของนิสิตในรูปแบบ Markdown ได้ดังนี้

---

#### 1. ตาราง `Advisors` (ข้อมูลอาจารย์ที่ปรึกษา)
[cite_start]ใช้สำหรับจัดเก็บข้อมูลของอาจารย์ที่ปรึกษาโครงงาน ซึ่งปรากฏอยู่ในตารางโครงงาน[cite: 6].

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **advisor\_id** | INT (PK) | รหัสเฉพาะของอาจารย์ (Primary Key) |
| advisor\_name | VARCHAR | [cite_start]ชื่อ-นามสกุลของอาจารย์ [cite: 6] |
| email | VARCHAR | อีเมลสำหรับติดต่อ |
| department | VARCHAR | ภาควิชา |

---

#### 2. ตาราง `AcademicTerms` (ข้อมูลภาคการศึกษา)
[cite_start]ใช้สำหรับจัดเก็บข้อมูลปีและภาคการศึกษาต่างๆ ที่เปิดสอน[cite: 2, 5].

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **term\_id** | INT (PK) | รหัสเฉพาะของภาคการศึกษา (Primary Key) |
| academic\_year | INT | [cite_start]ปีการศึกษา (เช่น 2568, 2567, 2566) [cite: 5] |
| term\_name | VARCHAR | [cite_start]ชื่อภาคการศึกษา (เช่น 'เทอมต้น', 'เทอมปลาย', 'ภาคฤดูร้อน') [cite: 5] |

---

#### 3. ตาราง `Projects` (ข้อมูลโครงงาน)
[cite_start]เป็นตารางหลักสำหรับจัดเก็บข้อมูลของแต่ละโครงงาน[cite: 6].

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **project\_id** | INT (PK) | รหัสเฉพาะของโครงงาน (Primary Key) |
| project\_name | VARCHAR | [cite_start]ชื่อโครงงาน [cite: 6] |
| group\_name | VARCHAR | [cite_start]ชื่อกลุ่ม [cite: 6] |
| **advisor\_id** | INT (FK) | [cite_start]รหัสอาจารย์ที่ปรึกษา (อ้างอิงถึง `Advisors`) [cite: 6] |
| **term\_id** | INT (FK) | รหัสภาคการศึกษาที่ทำโครงงาน (อ้างอิงถึง `AcademicTerms`) |
| abstract | TEXT | บทคัดย่อของโครงงาน |

---

#### 4. ตาราง `Students` (ข้อมูลนิสิต)
[cite_start]ใช้สำหรับจัดเก็บข้อมูลของนิสิตที่เป็นสมาชิกในโครงงาน[cite: 6].

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **student\_id** | VARCHAR (PK) | รหัสนิสิต (Primary Key) |
| student\_name | VARCHAR | [cite_start]ชื่อ-นามสกุลของนิสิต [cite: 6] |
| email | VARCHAR | อีเมลสำหรับติดต่อ |

---

#### 5. ตาราง `ProjectMembers` (ตารางเชื่อมข้อมูลนิสิตและโครงงาน)
ใช้สร้างความสัมพันธ์แบบ Many-to-Many ระหว่างตาราง `Projects` และ `Students`.

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **project\_id** | INT (FK) | รหัสโครงงาน (อ้างอิงถึง `Projects`) |
| **student\_id** | VARCHAR (FK) | รหัสนิสิต (อ้างอิงถึง `Students`) |

---

#### 6. ตาราง `DocumentTemplates` (ข้อมูลเทมเพลตเอกสาร)
[cite_start]ใช้สำหรับจัดเก็บลิงก์ดาวน์โหลดไฟล์เทมเพลตสำหรับทำเล่มรายงาน[cite: 8, 14, 15].

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **template\_id** | INT (PK) | รหัสเฉพาะของเทมเพลต (Primary Key) |
| template\_name | VARCHAR | [cite_start]ชื่อประเภทเอกสาร (เช่น 'หน้าปก', 'ใบรับรอง', 'บทคัดย่อ') [cite: 15] |
| pdf\_url | VARCHAR | [cite_start]URL สำหรับดาวน์โหลดไฟล์ .pdf [cite: 15] |
| docx\_url | VARCHAR | [cite_start]URL สำหรับดาวน์โหลดไฟล์ .docx [cite: 15] |

---

#### 7. ตาราง `SubmissionDocumentTypes` (ประเภทเอกสารที่ต้องส่ง)
[cite_start]ใช้กำหนดประเภทของเอกสารที่นิสิตต้องอัปโหลดส่งในระบบ[cite: 16, 23].

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **doc\_type\_id** | INT (PK) | รหัสเฉพาะของประเภทเอกสาร (Primary Key) |
| doc\_code | VARCHAR | [cite_start]รหัสเอกสาร (เช่น 'CS01', '02', '03') [cite: 17, 18, 19, 20, 21] |
| doc\_name | VARCHAR | [cite_start]ชื่อเต็มของเอกสาร (เช่น 'ไฟล์เอกสารโครงร่าง') [cite: 23] |

---

#### 8. ตาราง `SubmittedDocuments` (ข้อมูลเอกสารที่นิสิตส่ง)
[cite_start]ใช้สำหรับบันทึกไฟล์เอกสารที่แต่ละโครงงานได้อัปโหลดเข้ามาในระบบ[cite: 16, 25, 28].

| ชื่อคอลัมน์ | ชนิดข้อมูล | คำอธิบาย |
| :--- | :--- | :--- |
| **submission\_id** | INT (PK) | รหัสเฉพาะของการส่ง (Primary Key) |
| **project\_id** | INT (FK) | รหัสโครงงานที่ส่งเอกสาร (อ้างอิงถึง `Projects`) |
| **doc\_type\_id** | INT (FK) | รหัสประเภทเอกสารที่ส่ง (อ้างอิงถึง `SubmissionDocumentTypes`) |
| file\_path | VARCHAR | ตำแหน่งที่จัดเก็บไฟล์ที่อัปโหลด |
| uploaded\_at | DATETIME | วันและเวลาที่อัปโหลด |
| uploader\_student\_id | VARCHAR (FK) | รหัสนิสิตผู้ที่ทำการอัปโหลด (อ้างอิงถึง `Students`) |

### แผนภาพความสัมพันธ์ (Entity-Relationship Diagram - ERD)

* **Advisors** `1..*` ----- `1` **Projects**: อาจารย์หนึ่งคนสามารถเป็นที่ปรึกษาได้หลายโครงงาน
* **AcademicTerms** `1..*` ----- `1` **Projects**: ภาคการศึกษาหนึ่งมีได้หลายโครงงาน
* **Projects** `1..*` ----- `*..*` **Students** (ผ่านตาราง `ProjectMembers`): โครงงานหนึ่งมีนิสิตได้หลายคน
* **Projects** `1..*` ----- `1` **SubmittedDocuments**: โครงงานหนึ่งต้องส่งเอกสารหลายประเภท
* **SubmissionDocumentTypes** `1..*` ----- `1` **SubmittedDocuments**: ประเภทเอกสารหนึ่งสามารถถูกส่งได้จากหลายโครงงาน
